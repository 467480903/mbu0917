# 两个 Apriltag 的视觉调平测试

入口：`test_apriltag_alignment.py`。辅助实现：`apriltag_alignment_support.py`。
不修改或重启服务，不依赖本测试进程加载 GDK；使用当前的 g2 和独立 Apriltag MQTT 服务。

## 目标与限制

这里的“平行”指**两个标签中心的连线与图像水平轴平行**，不是两个标签的姿态互相平行，
也不表示机器人已正对标签所在平面。图像 Y 轴向下，斜率为 `(y2-y1)/(x2-x1)`，
倾角为 `atan2(y2-y1, x2-x1)`。按图像 X 从小到大排列中心，固定跟踪同一对 ID。

底盘、腰部左右转是偏航，并不能普遍消除相机横滚或标签本身的高度差。
因此不根据斜率正负硬编码左右转：首步小角度探测，再根据实测的倾角变化与实际转角估计修正量。
视觉响应很小、同侧误差继续增大或达到次数上限就结束，不宣称一定调平，也不自动回到初始角度。
只有满足误差阈值才报告 `reached=true`；运动后未达标退出码为 2，异常为 1。

## 按斜率预测转角，过头后反向补偿

两个阶段独立估算响应系数，不能把底盘的系数直接用于腰部：

1. 第一次：底盘请求 2°，腰部请求 0.5°，测量实际转角与图像倾角变化。
2. 计算 `k = 图像倾角变化 / 实际转角`，下一次预测修正量为
   `-0.9 × 当前图像倾角 / k`，一次执行预算内较大的修正，而不是固定小步挪动。
3. 如果倾角正负改变，说明越过水平位置。在已测到的正负误差采样点之间线性插值，
   估计零误差位置，再从当前位置反向补偿。过头本身不再触发旧版的“变差即停止”。
4. 第 3、4 次依据新测量再次估算/补偿；最多 4 次，首步探测也计数，达标提前结束。

例如实测转动 +2° 后，倾角从 -3° 变为 -2°，则 `k=0.5`，
下次预测转角是 `+3.6°`（仍受本阶段预算限制），不是再固定转 2°。
图像倾角由 `degrees(atan(斜率))` 得到，不能直接把它当成偏航角。
底盘剩余预测修正不足 1.5° 时交给腰部阶段，不强行放大到最小步长而反复过冲。
这是一种局部近似模型，不保证任何相机姿态、标签布置都能在 3～4 次内收敛。
仍通过 MQTT 调用 `g2.py` 拍照/运动、`apriltag.py` 识别，不修改服务、不直接调用 GDK。

## 使用

在机器人上运行（从任意工作目录均可）：

```bash
# 仅拍照与识别：不会发布运动命令，推荐先检查输出
python3 /data/wxf/mbu0917/test/services2/test_apriltag_alignment.py

# 现场运动测试，每次转动前都需要人工按回车确认
python3 /data/wxf/mbu0917/test/services2/test_apriltag_alignment.py --move

# 指定标签，保存新日志文件；已有日志不会被覆盖
python3 /data/wxf/mbu0917/test/services2/test_apriltag_alignment.py \
  --move --ids 1 2 --log /tmp/apriltag_alignment_run1.jsonl
```

Python 需要 paho-mqtt 2.x。识别由已有 `.venv-apriltag` 服务执行，本测试不用安装视觉库。
`--probe-sign -1` 可改变第一次探测方向；默认正方向。
`--tolerance` 默认 0.3°，可设 0.1～2°。退出日志中包含每张照片文件名、标签中心、斜率、倾角与每次转角。

## 顺序和安全边界

1. 每次观测拍摄三张头部 RGB 照片，逐一识别**本次返回的文件名**，不读共享 latest 文件。
   倾角取中位数，三帧波动超过 0.3°则停止。默认要求恰好两个标签，丢失/重复 ID、
   非有限坐标、水平间距不足 50 像素都停止。
2. 底盘先调整，最多 4 条纯旋转命令，平移量始终为零；首步 2°，后续单次最多 4.5°，角速度 2°/秒，
   累计指令绝对角度不超过 8°。现有 `relative2` 内部到位容差为 0.02 rad（约 1.15°），
   因而请求角度下限采用 1.5°，必须检查实时角度反馈，不能把 done 当精确到位。
3. 再调整腰部 `idx05_body_joint5`（URDF 轴向 `0 0 1`），最多 4 条命令；
   首步 0.5°，后续单次最多 1.25°、累计不超过 2°，速度 0.03 rad/s。目标读取当前角度计算，
   使用项目 `web/meshes/model.urdf` 限位，留出 5°裕量。其余腰腿轴由现有服务保持当前角度。
   第 2/3 次调整预留底盘 1.5°、腰部 0.25°的后续补偿预算，第 4 次可使用剩余预算。
4. 每条运动等待匹配唯一 `time`、`cmd`、`type` 的 `/humanoid/done/`，拒绝历史 retain 报文，
   不把普通 response 当作完成。收到 done 后等待 1 秒，再读新鲜角度状态并重新拍照。
5. 任一阶段已达误差阈值就提前结束。超时、服务错误、断线、实际运动方向异常会终止整个测试。
   未确认运动完成时异常退出会尝试发送软件急停，不自动解除；网络故障时不保证送达，
   现场必须能够使用实体急停。软件急停不是安全认证急停的替代品。

现场先固定标签与头部姿态，确保底盘、腰部、两臂整个旋转范围无人无障碍；
停止其他程序，避免网页或其他 MQTT 客户端同时控制机器人。每次确认后拍照期间不要移动标签。
默认观察不达标不代表必须转动，尤其纯横滚倾斜应重新检查相机/标签安装方式。
AI 不自动运行此运动测试；实际运动由现场人员确认执行。
